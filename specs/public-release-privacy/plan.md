# public-release-privacy 实施计划

> 2026-10-30：spec第1版已获用户Gate1批准（7R/25AC）。本计划待独立Checklist，尚未进入Implement。范围仅公开内容脱敏、必要配置边界与已获准的历史清理；其他远端、服务、数据库和原始材料不动。

## 1. 边界与顺序

1. 在仓库外备份全部Git引用、当前工作区（含未提交治理/规格文件）、原始归档，核验哈希及可恢复性。
2. 记录GitHub上两个已获准分支的完整旧OID，作为唯一发布租约；不存在的标签/其他分支不创建、不删除。公开记录不刊载旧OID、私人身份或租约原值。
3. 独立核对设计，再拆Tasks/Analyze；由Astra按非重叠文件范围实施，主会话复核和复跑。
4. 先完成当前树脱敏、配置/脚本回归、文档/发布扫描，再在独立本机副本中演练历史清理。原工作副本及仓库外备份不被过滤器覆盖。
5. 扫描候选的两个分支全部可达提交内容、提交消息、作者和提交者；验收重写的树与当前候选相符，分支祖先关系仍可用于正常PR。
6. 独立Review检查实际差异、历史过滤脚本与演练、兼容性和未验风险；未获必要Gate2前不发布新主分支代码，不借历史重写绕过合并闸门。
7. 发布时重新核对租约，用一次显式、原子的受保护更新仅替换`origin`的`main`和`feat/catalog-foundation`；任何并发新提交/分支保护拒绝均停止，不改为无条件force、不改保护规则。
8. 发布后从GitHub重新取得这两个分支并复扫；再按已批准阶段建立PR/合并。旧原始引用只保留在非公开备份，不推送。部署远端仍保留原历史，未来同步需另行安排，不在本轮处理。

## 2. 当前公开树

### 2.1 文档与归档

- 检查所有受版本控制文本，不仅Markdown。对README、AGENTS、docs、specs、注释与示例逐项保留/脱敏/移出公开树。
- 删除个人身份、私人入口/网络/设备实例/宿主布局、接收平台/下载任务、原账户额度和定位信息；使用角色、环境变量、中性示例描述，不把示例说成真实部署。
- 保留学术机构、馆藏号、IIIF/署名/许可限制、来源未知、领域数据规模、真正验收数字和失败记录。实际运行数据不改写。
- 归档`handoff/`原件统一保存在仓库外，不继续向公开历史提供含私人内容的原始提示词、命令、日志、来源映射与校验清单。公开树提供精简`handoff/README.md`及`docs/verification.md`，明确为脱敏摘要，记录各阶段实际结果、模型/角色、方法、限制与旧证据的适用边界。
- 公开验证摘要使用不含旧SHA片段的稳定候选别名，对应关系仅非公开留存；不将旧提交哈希当作公开可复现的新候选，也不为隐藏失败改变数字。
- 当前必要一致性检查从原工具保留能力迁至`tools/check_docs.py`；原私有调度脚本不作为公共操作入口。更新所有失效链接，原始详细证据只描述为非公开档案，不发布私人路径。
- 对冻结catalog规格/计划的修改仅是明确标识的隐私发布修订：需求ID、AC、安全/许可和领域语义不变，不伪称仍与脱敏前逐字相同。若实际需求/算法需要变化，停止回Clarify。

### 2.2 运行默认值和部署文件

| 范围 | 最小调整 | 保持的契约 |
|---|---|---|
| catalog配置 | v0开发后备值改为明确的本地示例；正式Compose要求部署者显式提供URL/绑定与宿主输入。不得退回实际私人入口 | URL入口校验、secret缺失拒绝、原API权限/结构、无凭据字面量 |
| catalog Compose / env example | 宿主数据/备份/cache/v0环境文件/PG目录改为`DH_HOST_*`配置；原两项绑定变量不含私人默认值，env示例为空占位并说明必填 | 只读输入4项、外置PG、无DB端口、API明确绑定、512m/384m且memswap相等、原启动/健康/用户策略 |
| 根Compose | 用部署方提供的宿主目录/中性相对目录替换私人绝对布局，删除设备实例和入口注释；保留原服务、命令和限额 | v0及两个生成器的职责、原图rw/ro策略、内存/线程/守卫值不变 |
| 旧辅助脚本 | 部署工作目录由环境给出或脚本所在目录推导；数据/cache用既有角色环境变量或中性挂载路径，不内置私人宿主位置 | 不下线旧通道、不改队列/ID算法、不真的启动Docker或写真实材料 |
| 来源事件标签 | 私人接收渠道改为中性且可区分的接收事件，详细记录私下保存；规则版本正常提升 | 收藏机构/谱系/许可/署名及严格度不变，不覆写旧DB批次；不谎称直接授权 |

配置名称以现有`DH_*`、绑定变量风格为准，不引入配置框架或模式矩阵。公开文档同步列出升级前需由部署方填写的参数；现有部署文件不在本轮改动。

### 2.3 旧执行记录的绝对路径兼容

目前解析器识别容器挂载前缀和两个私人宿主前缀。不能简单删除后两个分支，否则旧记录会丢失派生关系。

- 容器角色前缀`/data/`、`/backup/`保留；私人宿主前缀移为可选配置`DH_RECORD_DATA_ROOT`、`DH_RECORD_BACKUP_ROOT`，公开代码/测试只使用中性示例。
- 仅在`config.py`入口读取/规范化配置为类型确定的data/backup前缀映射；为空则仅识别容器/相对记录。宿主输入根与记录中的旧路径根分开：它们可能不相同，不猜测或扫描日志指向的宿主目录。
- 设置随API的PreparedImport.execute传入compute_import，再到resolve_derivations/_read_records/_parse_log/_record_path；新增参数为空映射的向后兼容默认值，现有直接调用不需要新参数。
- `_record_path`仍只构造库存键，保留相对路径/越界检查；不增加文件系统读取、目录遍历、动态匹配或根目录猜测。派生择最后成功、完整来源及许可继承算法不变。
- 补真实合成记录测试：无私人默认值；配置的中性宿主data/backup前缀仍产生原有边；未配置的绝对路径显式异常；容器/相对路径及失败路径旧回归保留。补入口配置及API传递的验证，不复制被测路径算法。

## 3. 隐私扫描与原件

### 3.1 两层检查

- 公开`tools/check_public_release.py`检查全部文本、旧归档残留、明显私人路径/地址形态、错误的私有可见性现行指令、文档链接等。测试仅用合成身份、保留示例域名和中性路径，不把真实禁止值硬编码回测试或扫描器。
- 机密规则文件仅在仓库外：由初始盘点和提交者元数据整理实际身份、域名、网络地址、工作站/宿主位置、接收平台及原始操作线索。扫描器允许显式接收此文件，报告仅输出类别、相对文件位置和计数，不回显原值或上下文。
- 通用产品名、机构/作者学术引用、标准容器路径、明确合成夹具不机械删除。每个初始候选命中文件都要有处理/保留原因，后续新文件也纳入覆盖。
- 全历史复扫须涵盖两分支全部可达blob、提交消息、author/committer信息，不能只扫描tip或grep工作区。

### 3.2 原始与公开证明

仓库外的原件、完整备份、扫描明细、旧新OID映射、过滤器规则/日志为私有操作资产。公开只保留脱敏的覆盖计数、摘要、工具说明、测试/评审结果、剩余限制及公开产物的实际新哈希。原始哈希不是已编辑公开文件的哈希，不混用。

## 4. 历史演练与受保护发布

### 4.1 不就地破坏工作副本

使用现有Git和Python标准库，在仓库外独立副本中进行。保留完整备份和私有OID映射，不安装应用依赖或新增agent框架。过滤器实现交指定Astra，主会话独立检查。

- 以Git原生历史重写机制（`git filter-branch`的index/env/message filter）处理两个本机候选分支。先在独立副本验证小样本，再处理完整引用；不自造fast-import协议解析器，也不对原工作副本直接使用破坏性清理。
- index过滤器按实际树/模式保留代码与安全目标，移除私人归档，使用仓库外规则生成并缓存脱敏blob替换；文件mode保持，非目标文件逐字保留，不能只替换当前tip。
- 文本替换仅针对已分类私人值与确定的文档重述；历史源码按合适的中性值保持语法/原版本结构，不把当前完整新实现灌入早期版本。过滤后的历史不是当时测试的逐字输入，公开验证摘要明确该区别。
- author和committer统一为非个人贡献者身份及`example.invalid`邮箱；保留提交Unix时间、规范为UTC。提交消息同样脱敏，不带私人原值或旧提交SHA片段。
- 审核后公开记录只引用新的公开候选/树与非敏感别名，私有原件与已发布旧OID只在非公开映射内保存。

### 4.2 租约与引用

发布前实时核对两个远端完整OID仍等于最初已记录租约。使用显式分支refspec与两个精确`--force-with-lease=refs/heads/<name>:<expected-old-oid>`，并使用`--atomic`，不使用裸`--force`、`--mirror`或带备份引用的`--all`推送。服务器不支持原子更新、OID变化或分支保护拒绝时停止并报告，不能自动覆盖新工作或放宽保护。

发布后从远端新取两个引用，以新副本核对OID、每个可达提交与全部内容、作者/提交者、祖先关系、当前树及公开产物校验。只报告已验证引用的清理状态；PR缓存、平台保留旧对象、分叉和既有副本无法保证撤回。部署远端保持旧历史，需要未来部署授权和专门同步安排。

## 6. 验证、限制与停止条件

- 本机使用现有catalog虚拟环境与pytest。完整运行`catalog/tests`及`catalog/acceptance`；新公开工具测试用标准库和现有pytest，不新增测试框架。
- 生产/脚本源码做UTF-8、LF、Python3.12 AST/编译和shell语法检查，静态语法不冒充目标环境运行。
- 数据库/SQL/身份算法不得改。旧目标446项属于原候选，只能由审核员据实际差异判断哪些旧证据仍可支持，不能冒称新候选真PG或足规模通过。
- 当前未获新的私人主机隔离数据库测试许可，不连接该环境。若独立审核认为新参数传递/版本变化必须新目标复验，停在未验，单独请求受限合成验证许可；不以本机skip或旧证据代替。
- 历史过滤用有害输入合成仓库验证（两个分支、根与合并提交、重复blob、不同mode、带空格路径、消息/身份）；验证原件不变、当前树一致、授权引用限定、租约不匹配拒绝。不引入和任务无关的复杂防御机制。
- 任一实际私人值残留、归档数字/许可语义不一致、代码回归、租约变化或未获必要审批均停止发布。Gate1与历史授权不是可跳过Review或必要Gate2的理由。
