# Feature: public-release-privacy 公开仓库隐私脱敏（spec.md）

> 状态（2026-10-30）：**用户已明确批准Gate1，本版7R/25AC冻结，允许进入Plan**。批准范围含最小必要源码、配置和脚本脱敏；用户同时明确授权清理已公开Git历史与提交者信息，并仅对`origin`的`main`和`feat/catalog-foundation`作受保护强制更新。其他远端/引用、部署与真实导入不在授权内；不可将此授权代替新差异的独立Review/必要Gate2。可见性决策见D-019。

## 1. 背景与动机（why）

- 代码仓库含面向私人运行环境的文档、操作与审核归档；这些内容原按非公开语境编写，不能直接当作公共软件说明。
- 初步只读扫描覆盖457个受版本控制文件和1个本机待提交记录，其中403份文档/归档、55份源码/运行文件。136份文档/归档及19份源码/配置出现候选命中，部分为通用技术名或合成测试，不能把候选数当作已确认泄漏数。
- 真实运行地址、宿主路径和资料接收渠道也存在于可执行默认值中。仅修改Markdown不足以满足公开发布隐私目标。
- 本地全部可达历史含730个不同文件对象，其中332个对象出现候选命中；65条提交记录涉及同一非匿名提交者邮箱。旧提交和提交者身份不随普通文件修改而消失。
- 明细、原值和私有映射仅保存在仓库外；已完成Git与未提交工作区的本机备份，不将敏感扫描原文重新提交到公开仓库。

## 2. 目标与非目标

### 目标（what）

- 公开代码与文档不再包含真实个人部署、个人账户或个人接收渠道信息；所有公开示例与运行默认值有清楚的非私人边界。
- 保留软件用途、领域与学术事实、来源不明和许可约束、可追溯要求、测试结论与已知风险，不以脱敏掩盖问题或制造授权。
- 对所有文档形式、源码注释、默认值与归档进行一致检查，避免只清理README或只检查文件扩展名。
- 公共衍生文档与私有原件分离；可公开的证据仍能说明测试对象、方法、结果、审核范围与局限。
- 明确Git历史和提交者元数据的剩余暴露及处理授权边界，清理状态可验证，不虚报完成。
- 在脱敏实施、回归及独立审核完成后，再恢复已获批准的交接、PR与合并流程。

### 非目标

- 不更改仓库为Private，不更名或转移仓库；不承诺隐藏公开托管平台本身必然显示的仓库所有者身份。
- 不改写私人材料、已导入数据库或运行配置，不操作或重启私人服务器/容器，不部署、不触发真实导入。
- 不新增功能、修改身份归并/标注/许可算法，不放宽内存或认证红线，不借机修复无关问题。
- 未获额外授权前，不重写已发布历史、不强制推送、不删除远端分支/标签或改写提交者信息。
- 不保证撤回已被第三方取得的副本，也不把本次规则扫描当作对所有未知秘密格式的绝对无泄漏证明。

## 3. 需求条目

### R-001 公开边界与资料保全

- **what**：公开代码与通用说明，私人运行事实及原始审核资料保留在非公开位置；清理不丢失原件，也不通过新审计材料再次泄露原值。
- **验收规则**：
  - [ ] AC-001-1 D-019与公开说明区分代码公开、资源许可及服务访问范围，其他规范不存在仍要求将本仓库改私有的现行指令。
  - [ ] AC-001-2 修改前的已提交历史、当前工作区变化和必要原始证据有仓库外副本与完整性记录，不复制真实运行凭据或原材料入库。
  - [ ] AC-001-3 公开扫描结果仅含脱敏分类、文件范围、结论和限制，不包含被删除的原值、私有映射、私人邮箱或原始上下文。

### R-002 全部公开文本的隐私处理

- **what**：检查并处理全部受版本控制文本及待提交文本，包括规范、README、注释、操作模板、审核提示词、日志、JSON/JSONL、元数据及校验清单，不限于Markdown。
- **验收规则**：
  - [ ] AC-002-1 验收清单覆盖待发布树的全部文本文件；逐项记录处理、保留或排除原因，未识别格式明确待核，不漏掉归档与隐藏文件。
  - [ ] AC-002-2 真实个人账户/邮箱/姓名、私人域名及网络地址、私人网关拓扑、工作站/宿主路径、设备实例、个人模型账户额度等不再出现在公开内容中；通用产品名、程序角色、合成夹具和公开学术机构不被机械误删。
  - [ ] AC-002-3 公开地址与路径示例明确为示例或需用户配置；不把替代值伪称为实际已部署环境或真实测量。
  - [ ] AC-002-4 新增规范、扫描器、测试输入和脱敏证明自身不包含真实禁止公开值；不为验证隐私将这些值重新硬编码入库。

### R-003 资料渠道隐私与学术纪律

- **what**：对外使用不识别个人获取渠道的接收事件/来源描述，详细接收记录私下留存；不得借此删除学术来源和许可风险。
- **验收规则**：
  - [ ] AC-003-1 公开树不再披露个人接收平台、账户、分享链接、下载任务或可回溯个人操作的接收细节。
  - [ ] AC-003-2 保留收藏机构、馆藏号、谱系与第三方加工/来源未知的区分，以及许可未知/仅限研究/对外展示限制，不改称已获直接授权或开放许可。
  - [ ] AC-003-3 公开描述能区分不同接收事件与材料类别，私有记录仍可供授权运维/研究使用；不伪造或覆盖过去批次的实际来源与作者。

### R-004 源码、默认值与运行文件的最小必要脱敏

- **what**：公开文档清理不能被源码、脚本、运行配置或测试中的真实默认值抵消；必要运行参数由部署方提供，公开代码使用中性、明确的边界。
- **验收规则**：
  - [ ] AC-004-1 可执行默认值、部署文件、辅助脚本和注释中不残留真实个人入口、个人存储布局或个人接收渠道；对配置缺失的行为明确，不以私人环境作隐式后备。
  - [ ] AC-004-2 调整仅限已说明的隐私相关文本、配置边界及必要测试，身份/归并/许可算法、数据结构、事务锁、只读挂载、内存硬限和认证拒绝策略保持；如无法保持须先报告并回到Clarify。
  - [ ] AC-004-3 不修改已部署文件、实际账户、数据库或原始材料。新公开代码与旧运行环境的区别及未来部署前须补充的参数清楚列明。
  - [ ] AC-004-4 所有代码修复由指定独立实施模型完成，主会话复核与复跑；真实文件/SQL/HTTP行为测试不以复制业务逻辑或削弱旧断言替代。

### R-005 归档原件与公开衍生版本

- **what**：历史审核/操作记录中的私人信息不能因「原文不可改」继续公开；原件非公开保全，公开内容明确为脱敏衍生材料或经核对的摘要。
- **验收规则**：
  - [ ] AC-005-1 被处理的归档有仓库外原件；公开版本明确标注脱敏/摘要，不冒称逐字原文。
  - [ ] AC-005-2 保留实际模型/审核角色、候选范围、通过/失败/跳过数、退出状态、资源限制、数据规模、审核结论及未验边界，不把失败改为成功、不隐藏测试跳过。
  - [ ] AC-005-3 依赖内容的校验和清单从实际公开产物重新生成，原件与公开衍生记录不混用哈希；私有源路径/映射不进入公开清单。
  - [ ] AC-005-4 文档链接和交接入口可用。私人材料不再有假装可公开访问的链接；原始详细证据仍仅非公开保留，公开摘要足以说明证据边界。

### R-006 Git历史与提交者信息的独立授权

- **what**：区分当前发布树脱敏与已公开历史清理。旧文件内容、提交消息、作者/提交者身份及分支/标签引用均纳入只读盘点；破坏性操作不得从普通编辑权限推定。
- **验收规则**：
  - [ ] AC-006-1 对本地可达历史及已公开分支的范围、候选私人内容和提交者信息形成不含原值的摘要，不把普通提交当作历史清理完成。
  - [ ] AC-006-2 历史处理方式、受影响引用/提交ID、备份、协作者影响及验证条件先提交用户确认；未授权不重写历史或强制推送。
  - [ ] AC-006-3 最终报告明确当前树和历史各自是否已清理、哪些引用仍未处理、哪些副本无法保证撤回；未清历史不得使用「全部已隐去」或等价结论。

### R-007 验证与交付门槛

- **what**：以完整复扫、人工核查、文档检查、必要的真实实现回归和独立评审确认清理结果，之后才恢复已批准的软件交付。
- **验收规则**：
  - [ ] AC-007-1 对最终待发布树复扫全部文件，并人工核查例外、示例、学术来源、公开归档和源码默认值；无未处置的真实个人信息命中。
  - [ ] AC-007-2 文档引用/格式、生成清单与来源语义一致，旧冻结需求的隐私用词变化不冒称功能需求未变的逐字原件；原需求ID与许可/安全目标保留。
  - [ ] AC-007-3 运行全部适用本机测试，代码/配置变化取得对应新候选验证，跳过与未测目标如实记录；不得沿用旧候选全绿或旧规模实测冒充新改动已验证。
  - [ ] AC-007-4 独立审核实际隐私差异、证据和功能/运维影响，按现有流程取得必要人工批准后，再进行Handoff/PR/合并；本轮不部署或真实导入。

## 4. 约束与依赖

- 遵守AGENTS工作流；本版已获用户Gate1批准，实施仍须完成Plan/Checklist/Tasks/Analyze，由指定Astra实施、独立Claude审核，通道规则不变。
- D-019已获用户确认「保持公开且清理隐私」的方向；D-009部署通道、D-005内存安全、D-008原图写入边界、D-012许可与D-018服务隔离不放宽。
- `catalog-foundation`原软件Gate2批准保留，但其PR/合并等待本次公开发布清理与历史处置决定；不把原批准推定为未审新代码或历史重写批准。
- 原始数据、私有配置与凭据永不入库；本轮不创建或连接私人服务、不推送部署远端。若代码变化需要目标隔离数据库复验，须在派发前明确取得该测试范围许可，仍非正式部署许可。
