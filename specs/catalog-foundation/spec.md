# Feature: catalog-foundation 目录底座（spec.md）

> Spec 阶段产物：按 what/why 写需求，不写技术方案。每条需求必须映射到具体的验收规则。
> 技术方案与实施细节在 plan.md；本文件由 Clarify 阶段持续修订直至无歧义。
> 状态（2026-10-27）：Spec 与 Clarify 完成（§5 的 10 项歧义已依据数据与 ADR 闭环），**待 Gate 1 批准**；批准后冻结。

## 1. 背景与动机（why）

- **身份不稳定**：v0 以「含 TIFF 的目录」为一卷，卷 ID 由磁盘路径派生（architecture.md §3.2），目录一改名，ID 和图块缓存就失效
- **一卷不等于一件文物**：同一件写卷分散在多个目录（法藏 849 个影像目录只对应 740 个编号，22 个编号同时有两类影像）；一个目录也可能涉及多件（名称含多个编号、散放文件）（plan.md §1.3）
- **来源、许可与出处没有记录**：材料来自第三方资料接收（接收事件 A）与 IDP 下载，混有第三方加工图；约 110 个冠以「敦煌遗书」的目录并非敦煌出土或出处待核（plan.md §1.3、D-012、D-015）
- **后续工作需要共同底座**：`name-normalization`、`annotation-workbench`、`catalog-browse` 都要以「写卷」为单位、身份稳定、带编号 / 影像 / 来源 / 出处的目录为基础（plan.md §8）

### 术语

| 术语 | 含义 |
|---|---|
| 写卷 | 一件物理文物（写卷、残片、册页，或刻本、拓本、绘画），目录中的一条记录 |
| 影像目录 | v0 意义上的「卷」：直接含影像文件的目录 |
| 影像 | 一个影像文件：TIFF、PSB、页图 JPG |
| 谱系 | 影像的来源类别：BnF 原图 / 第三方加工图 / 本地合成 / 国图 IDP 下载 / 未判定（plan.md §1.3） |
| 角色 | 影像在写卷中的作用：单幅整卷 / 分段 / 另一版本 / 已迁出的分片 / 合并长卷 / PSB 源文件 / 页图 |
| 出处认定 | 是否敦煌出土：已确认 / 待核 / 非敦煌，附依据（D-015） |
| 主编号 | 写卷的馆藏号（如 `P.2053`、`BD00001`）；没有馆藏号的写卷不设主编号 |

## 2. 目标与非目标

### 目标（what）

- 把全部现有材料导入统一目录，以写卷为单位，每件写卷有稳定的内部 ID
- 每件写卷记录：编号（多体系）、影像（含事实、谱系、角色、派生关系）、来源与许可、出处认定初值、原始记录
- 导入可以反复运行，追踪新增、变化与缺失
- 提供只读查询接口，供授权用户与后续 feature 使用
- 每次导入给出报告与异常清单

### 非目标

- 规范名称，以及题名、时代、尺寸等字段的解析（`name-normalization`）
- 标注、人工认定与修改的界面（`annotation-workbench`）
- 分类浏览界面、同一写卷多套影像中「首选影像」的选择（`catalog-browse`）
- 采集与关联外部资源，如法藏写卷的 IDP / Gallica 清单（Phase 2）
- 影像服务与查看（继续由 v0 承担）；修改原图目录与 v0；对外开放（D-012）

## 3. 需求条目

### R-001 导入范围

- **what**：导入 D-015 规定的全部现有材料——原图目录 `/srv/example/data` 下 5 个分类的影像（影像目录按 v0 规则识别：跳过以 `@`、`#`、`.` 开头的目录），以及备份目录 `/srv/example/backup` 的分片、PSB、国图卷的页图与 IIIF 清单、`.txt` 说明。以 `.` 开头的隐藏文件一并导入（§5 Q-003）
- **验收规则**：
  - [ ] AC-001-1 v0 同一时刻索引中的每个影像目录，在目录中都至少对应一件写卷；导入报告给出两边的数量对照，差为 0
  - [ ] AC-001-2 原图目录中每个 TIFF / BTF（含隐藏文件）、备份目录中每个 TIFF、每个 PSB、国图卷 `pages/` 下的每个 JPG，在目录中有且只有一条影像记录；数量与导入时的磁盘文件数一致
  - [ ] AC-001-3 每个 `.txt` 说明、每个国图卷的 `manifest.json`、`report.json`、`index.json` 作为所属写卷的原始附件导入
  - [ ] AC-001-4 未导入的文件与目录（隐藏目录、系统目录、下载器的中间文件如 `.npy`）逐一列在导入报告中并注明原因

### R-002 写卷的识别与归并

- **what**：按「一件物理文物一条记录」把影像归入写卷（§5 Q-001、Q-002、Q-005）：
  1. 同一编号（体系 + 号 + 分件）的影像归入同一件写卷，不论分散在几个目录、属于哪个谱系
  2. 名为「分段」「分」「斷巻分段」「HD」等的子目录归入父目录的写卷
  3. 直接放在批次目录里的散放影像文件，每个文件一件写卷
  4. 名称含多个编号的，每个编号一件写卷，该目录的影像同时关联到这几件
  5. 分件写法各成一件写卷，并记录母号；母号本身有影像时另成一件
  6. 没有编号的影像目录各成一件写卷，不自动合并；疑似同一件的只列为合并建议
  7. 备份目录的分片按其在备份目录中的相对位置，归入原图目录中对应的写卷
- **验收规则**：
  - [ ] AC-002-1 同一编号的全部影像归入同一件写卷；例：P.2002 的 BnF 原图影像目录与第三方加工图影像归入同一件写卷，两套影像都在
  - [ ] AC-002-2 「分段」「分」「斷巻分段」「HD」子目录的影像归入父目录的写卷，角色分别为「分段」或「另一版本」
  - [ ] AC-002-3 散放影像文件各成一件写卷（2026-10-27 有 7 个，均在 `188敦煌001/2018年`），编号从文件名解析（如「（P.4508）」→ `P.4508`）
  - [ ] AC-002-4 名称含多个编号的影像目录（2026-10-27 有 7 个，如 `P3012+5564`、`P2661(+3735)`）：每个编号各成一件写卷，影像同时关联到这几件，写卷上记有「名称所示的合装或缀合」线索
  - [ ] AC-002-5 分件写法（`P.2504-1Pièce`、`P.2006-1`、`P.2222A`、`P2842-P2`、`BD00023a`）各成一件写卷并记录母号；按母号能查到它的全部分件（如 P.2504 的 4 个分件）
  - [ ] AC-002-6 没有编号的影像目录各成一件写卷；名称只差「上部 / 下部」「上卷 / 下卷」的成对目录列入合并建议清单，不自动合并
  - [ ] AC-002-7 备份目录的分片全部归入原写卷（2026-10-27 核查为 925/925），角色为「已迁出的分片」并记录原位置；对不上的列入异常

### R-003 稳定身份

- **what**：每件写卷、每条影像有内部 ID：不由磁盘路径派生，一经分配不再改变、不复用；重复导入、目录改名或移动都不改变已有 ID（只要影像文件本身未变）
- **验收规则**：
  - [ ] AC-003-1 同一份数据连续导入两次，所有写卷与影像的内部 ID 完全相同，不产生重复记录
  - [ ] AC-003-2 在测试数据中把一个影像目录改名、或移到另一个批次目录后重新导入，写卷 ID 与影像 ID 不变，旧路径记入路径历史
  - [ ] AC-003-3 内部 ID 不含磁盘路径信息，也不能由路径计算得到

### R-004 编号

- **what**：每件写卷记录全部编号：体系、原文写法、规范写法、出处（目录名 / 文件名 / IIIF 清单）、是否主编号。导入时校验号段，不合规的标为存疑而不丢弃。2026-10-27 已知的体系：BnF 伯希和汉文写卷号（`P.`）、国图 BD 号、分享者自编号（`WB`、`WA`）、《开宝藏》千字文帙号；国图卷 IIIF 清单中的 IDP 条目 ID 作为外部编号
- **验收规则**：
  - [ ] AC-004-1 伯希和编号的各种写法（`P2602`、`P.2033`、`P. 0901`、`p.2731`、`Pelliot chinois 2002`）解析为统一的规范写法（如 `P.2602`），原文写法逐字保留
  - [ ] AC-004-2 不在伯希和汉文写卷号段（2001–4099、4500–5043、5522–6038）内的 P 号标为存疑并列入异常（2026-10-27 为 P.0901、P.5257）
  - [ ] AC-004-3 国图卷目录名中的 BD 号与 IIIF 清单的 Pressmark 一致，不一致的列入异常；清单的 IDP 条目 ID 记为外部编号
  - [ ] AC-004-4 `WB`、`WA` 记为「分享者自编号」体系，《开宝藏》帙号（如「令字」）记为「开宝藏帙号」体系，两者都不作为主编号
  - [ ] AC-004-5 每件写卷最多一个主编号，且只能是馆藏号；只有分享者自编号或没有编号的写卷，主编号为空

### R-005 影像记录与谱系

- **what**：每条影像记录文件位置（相对路径与路径历史）、文件大小、像素尺寸、色彩模式与位深、分辨率、压缩方式、软件标签、谱系、角色、派生关系，以及国图卷对应的 IIIF 画布。谱系按 plan.md §1.3 的判定依据逐个文件判定
- **验收规则**：
  - [ ] AC-005-1 每个 TIFF 的像素尺寸、色彩模式、位深、分辨率、压缩方式、软件标签都已记录；读不了的文件列入异常，不中断导入
  - [ ] AC-005-2 每条影像都有谱系；判不出的标为「未判定」并列入异常。用 2026-10-27 数据导入时，按影像目录汇总的结果与核查一致（BnF 原图 447、第三方加工图 499、本地合成 12），不一致的逐项说明原因
  - [ ] AC-005-3 12 个 `合并长卷.tif` 记录派生来源：由分段拼接的关联到源分片（含备份目录中的），由 PSB 转换的关联到源 PSB，依据为 `cache/` 中 2026-10-21 的执行记录；不能确定的列入异常
  - [ ] AC-005-4 国图卷每个本地 TIFF 对应到 IIIF 清单中的画布（依据 `report.json`；2026-10-27 抽查 1,044/1,044 可对应），对不上的列入异常
  - [ ] AC-005-5 同一件写卷有多套影像时全部保留，并能区分每套影像的来源目录与谱系

### R-006 来源与许可

- **what**：每条影像记录收藏机构、获取渠道、许可条款、署名文本与展示策略，按 D-012 的默认规则自动填写，并标明该值来自默认规则
- **验收规则**：
  - [ ] AC-006-1 每条影像都有来源与许可记录，没有空值，且与 D-012 默认规则表一致：国图卷为 IDP 条款，署名取自清单（The National Library of China）；法藏 BnF 原图为 Gallica 条款；第三方加工图、日藏与其他材料为「未知」；本地合成继承源影像中最严格的一项
  - [ ] AC-006-2 每件写卷的展示策略取其全部影像中最严格的一项；Phase 1 所有写卷只在登录墙内可见
  - [ ] AC-006-3 获取渠道落到具体的转存或下载事件（如「第三方资料接收（接收事件 A；私人日期非公开）」「IDP IIIF 下载」），可在 plan.md §1.4 中查到对应记录

### R-007 出处认定初值

- **what**：每件写卷有出处认定（已确认 / 待核 / 非敦煌），附依据、判定者（规则或人）与时间。导入只按规则给初值：带合规 BD 号或伯希和汉文写卷号的为「已确认」，其余为「待核」；对有明确线索的写卷附「建议：非敦煌」及依据。「非敦煌」只能由人确认（§5 Q-004）
- **验收规则**：
  - [ ] AC-007-1 每件写卷都有出处认定、依据、判定者与时间，没有空值
  - [ ] AC-007-2 带合规 BD 号或伯希和汉文写卷号的写卷为「已确认」，其余为「待核」
  - [ ] AC-007-3 plan.md §1.3「并非都是敦煌写卷」所列的 18 个《开宝藏》目录，以及题名带明确线索的目录（清光绪写本、北齐尖山刻经、室町写、竹生島経、紫紙金字金光明最勝王経、大橋家来翰集），对应写卷为「待核」并附「建议：非敦煌」及依据；导入不把任何写卷直接定为「非敦煌」
  - [ ] AC-007-4 人工确认的结论在重新导入后保留，不被规则初值覆盖（用测试数据验证）

### R-008 原始记录保留

- **what**：导入不改写任何原始信息，只在其旁边增加结构化记录（D-013）
- **验收规则**：
  - [ ] AC-008-1 每件写卷、每条影像保留原始的目录名、文件名与相对路径，逐字不改（含尾标、全角符号、法文著录、隐藏文件名开头的点）
  - [ ] AC-008-2 国图卷的 `manifest.json`、`report.json`、`index.json`，以及每个 `.txt` 说明，原文可以完整取回

### R-009 重复导入与变化追踪

- **what**：导入可以反复运行（国图卷仍在增加）。每次导入是一个有记录的批次；新增、变化、缺失都有统计；磁盘上消失的影像只标记、不删除
- **验收规则**：
  - [ ] AC-009-1 新增的目录或文件在下一次导入后出现在目录中，其余记录不变
  - [ ] AC-009-2 磁盘上被删除的影像在下一次导入后标为「缺失」并记录发现时间；所属写卷及其编号、出处认定等信息不删除
  - [ ] AC-009-3 影像文件大小或修改时间变化时（如拼接工作台覆盖了 `合并长卷.tif`），影像记录更新，并保留变化历史
  - [ ] AC-009-4 每次导入留下导入记录：起止时间、各类数量（写卷；影像按谱系、角色；写卷按出处认定）、新增 / 变化 / 缺失数、异常数

### R-010 导入报告与异常清单

- **what**：每次导入后，可以取得人能读懂的报告与异常清单，作为 `name-normalization` 与人工确认的输入
- **验收规则**：
  - [ ] AC-010-1 异常清单每条含类别、对象、原文与说明；类别至少包括：编号存疑、编号与清单不一致、无编号目录、合并建议、隐藏文件与非隐藏影像同目录（待确认）、读不了的文件、谱系未判定、派生来源不明、未导入的文件
  - [ ] AC-010-2 用 2026-10-27 数据导入时，报告中的数量与 plan.md §1.3、§4.4 及 §5 所列的核查数一致，不一致的逐项说明原因：影像目录 6,096 个；原图目录 TIFF 32,121 个、备份分片 925 个、PSB 16 个、国图页图 JPG 2,997 个、`.txt` 477 个；隐藏文件 42 个（其中 10 个与非隐藏影像同目录）；散放文件 7 个；多编号目录 7 个；WB 号目录 46 个、WA 号 1 个；号段外的 P 号 2 个

### R-011 只读查询接口

- **what**：授权用户与后续 feature 通过接口查询目录，与 v0 共用同一套账号与登录状态（§5 Q-006）。本 feature 不提供修改目录内容的操作；触发导入仅限管理员。可查询：按编号（任一写法）查写卷；按编号体系、谱系、出处认定、有无异常、原始的分类目录 / 批次筛选写卷并分页；写卷详情（编号、影像、来源与许可、出处认定、原始记录、路径历史）；异常清单与导入记录
- **验收规则**：
  - [ ] AC-011-1 未登录的请求被拒绝；已登录的授权用户可以查询；只有管理员能触发导入
  - [ ] AC-011-2 按 `P.2002`、`P2002`、`Pelliot chinois 2002` 查询返回同一件写卷；按 `bd00001` 返回 `BD00001`（不区分大小写）；按 `WB 15` 返回对应的日藏写卷；按母号返回全部分件
  - [ ] AC-011-3 写卷列表支持上述各项筛选与分页；在 NAS 上、全量数据下，列表与详情查询的 P95 响应时间不超过 1 秒
  - [ ] AC-011-4 写卷详情给出它每个影像目录在 v0 查看器中的链接，点开即是对应影像
  - [ ] AC-011-5 接口中不存在修改目录内容的操作（触发导入除外）

### R-012 不影响 v0 与 NAS 安全

- **what**：导入只读访问原始材料，不改动 v0，遵守 D-005 内存红线与 AGENTS.md §4 的 NAS 操作约定
- **验收规则**：
  - [ ] AC-012-1 导入前后对比原图目录、备份目录与 v0 `cache/` 的文件清单与修改时间，没有任何写入、移动或删除
  - [ ] AC-012-2 导入不遍历 v0 的 `cache/` 目录，只读取其中指定的 2026-10-21 执行记录文件
  - [ ] AC-012-3 全量导入在 512 MB 内存上限内完成；导入期间 v0 的 `/api/health` 持续正常
  - [ ] AC-012-4 全量导入在 NAS 上 1 小时内完成；数据无变化时，再次导入 10 分钟内完成

## 4. 约束与依赖

- **决策**：D-005（内存红线）、D-007（登录墙与账号）、D-008 与 AGENTS.md §4（本仓库代码只经拼接工作台写原图目录；本 feature 不写）、D-012（来源与许可默认规则）、D-013（原始名称逐字保留；规范名称不在本 feature）、D-015（纳入范围与出处认定）、D-016（渐进迁移：本 feature 只交付后端与接口，不改 v0）、D-017（影像与 IIIF 画布的对应）
- **数据基线**：plan.md §1.3、§1.4、§4.4 与本文 §5 的 2026-10-27 核查数；数据会变化，验收以导入当时的磁盘为准，差异须说明
- **依赖的 feature**：无。不依赖 v0 工程线（`deps-lock`、`tests-foundation`）；与 v0 的接触只有三处：只读访问原图目录与备份目录、只读 `cache/` 中的 2026-10-21 执行记录、按 architecture.md §3.2 的卷 ID 规则生成指向 v0 查看器的链接
- **下游**：`name-normalization`（原始名称、编号解析结果、异常清单）、`annotation-workbench`（写卷 ID、出处认定建议、待确认清单）、`catalog-browse`（筛选维度）
