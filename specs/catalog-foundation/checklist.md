### 阻断问题

`[CHK-R002 / CHK-R004 / CHK-R007]` spec.md R-002 规则 1、AC-004-2、AC-004-5、AC-007-2；plan.md §4.3 — 「存疑」编号的用途未定义：spec 只说号段外的 P 号「标为存疑而不丢弃」，没说它能否作归并依据与主编号；「合规 BD 号」也没有定义（格式？是否要求与清单 Pressmark 一致？无清单时算什么？）。plan §4.3 伯希和行写「号段外标 doubtful…馆藏号，可作主编号、可归并」，同节末尾又写「主编号只取 ok 状态」，自相矛盾；若按「可归并」执行，plan.md §1.3 与 RK-14 明确指出的 P.0901（绢画、梵文写经、坐佛像 3 件不同物品）会被并成一件写卷。— 修法：spec 增加 Q-015：R-002 规则 1 限定为「合规的馆藏号」；AC-004-5 补「存疑编号不作主编号、不作归并依据，只作检索项」；定义「合规 BD 号」（如 `BD` + 5 位数字 + 可选小写字母，且与清单 Pressmark 一致；无清单时列异常并按格式判定）；AC-004-2 补预期「P.0901 的 3 个目录各成一件」。plan §4.3 同步删掉「可作主编号、可归并」。

`[CHK-R003 / CHK-P2]` spec.md R-003、AC-003-1～3；plan.md §2.1（308 跳转）、§3（item.status = merged、`item_redirect`）、§4.2.7 — spec 没有规定两件写卷合并 / 拆分时 ID 的去向，也没规定「目录改名导致馆藏号变化（如 P.2602 纠错为 P.2603）但影像未变」时 ID 怎么办：R-003 说 ID 不变，R-002 规则 1 按编号归并，两条在该情形下不能同时成立。plan 已自行设计 merged 状态、`item_redirect` 与 308 跳转，但没有任何 AC 对应，tasks 无法引用。— 修法：spec 增加 Q-016 并补 AC（如 AC-003-4：两件写卷因规则或人工合并时保留较早的 ID，被并入的 ID 永久重定向、不删除不复用；AC-003-5：写卷单元的馆藏号变化而影像未变时沿用原写卷 ID 并更新编号，新编号已有写卷时按合并规则处理）；plan §4.2.7 按此复核。

### 阻断问题

`[CHK-P1 / CHK-P2]` plan.md §4.2.3 第 1 条；§4.2.2 第 5 条 — 多编号单元按设计有多个目标 key（「可以有多个：多编号单元」）。重新导入时，对写卷 X = P.3012，「多数影像属于 X」的单元就是 `P3012+5564` 这个单元，其非空目标 key 有两个不同值，按第 1 条会被判「需要拆分」并记「规则要求拆分」异常，7 个多编号目录每次导入都会重复误报；与 AC-003-1（重复导入结果相同）、AC-002-4（影像同时关联多件）、AC-003-6 的本意冲突。— 修法：以单元为粒度比较 key 集合：一个单元自带多个 key 属于 R-002 规则 4 的「关联到多件」（目录改名新增编号时同样按规则 4 新增关联），不算拆分；只有「属于 X 的影像落在多个单元、且这些单元的 key 集合互不相同」才记「规则要求拆分」；plan §5 为 AC-003-1 / AC-002-4 补一条「多编号目录两次导入无异常」的测试。

`[CHK-R003 / CHK-02]` spec.md R-003「写卷单元的影像多数已属于某件写卷时沿用该写卷」；plan.md §4.2.3 第 1、3、4 条 — 「多数」的分母未定义：单元里从未登记的新影像是否计入？若计入，一个无合规馆藏号的目录（如 WB 目录）新增文件多于原有文件时，既不满足「多数属于 X」，也不属于 plan 第 3 条「影像不属于任何已有写卷的单元」，按字面会新建一件写卷与原写卷并存，违背 R-003 与 AC-009-1「其余记录不变」。plan 第 4 条的平局取法（serial 较小者）也只在 plan 中出现。— 修法：spec R-003 写明「多数」只在单元中已有身份的影像里计，从未登记的影像不计入；写明多件并列时取较早登记者；plan 第 1、3 条按此改写，并补「无编号目录新增文件后写卷 ID 不变、无新写卷」的测试。

`[CHK-R005 / CHK-02 / CHK-P1]` spec.md AC-005-2「一个影像目录的源影像谱系一致时取该谱系」；AC-006-1「本地合成继承源影像中最严格的一项」；plan.md §4.4 谱系规则、§6.3 A3 — 「源影像」无定义，且两处用法不同：按 AC-006-1 的「派生来源」理解，12 个只剩 `合并长卷.tif` 的目录会汇总为分片的谱系（第三方加工图），而非基线的「本地合成 12」。另外 plan 的谱系规则没有 `.psb` 分支（PSB 的软件标签为「不适用」、文件名不是 `native`），16 个 PSB 会全部「未判定」并记异常，所在目录变成「混合」，A3 无法得到 447 / 499 / 12。— 修法：AC-005-2 把目录级汇总口径定义为「该影像目录直接包含的 TIFF / BTF 的谱系」（与 plan.md §1.3 的目录分类口径一致），PSB、JPG 不计入；plan §4.4 为 `.psb` 增加谱系规则（第三方加工图或单列一类），并写明页图、预览图走国图规则。

`[CHK-P1 / CHK-P2]` plan.md §4.1 第 2 步 vs spec.md AC-012-2、plan.md §5 AC-012-2 — 导入「以 `users.json` 中第一个管理员的身份」签发会话，意味着导入过程打开了 `cache/users.json`，而 AC-012-2 要求导入只打开指定的 2026-10-21 执行记录文件，对应测试 `test_v0_cache_only_whitelist_opened` 会在这一步失败；JSON 对象的「第一个管理员」也没有确定顺序。— 修法：API 触发时用触发者自己的身份签发会话，命令行触发时用 `catalog/.env` 配置的专用账号名签发，导入过程不读 `users.json`；或在 AC-012-2 明确把 `users.json` 列为导入允许打开的文件并写明用途。

`[CHK-R002 / CHK-02]` spec.md §1 术语「子目录词表」「写卷单元」；R-001；AC-002-2；AC-010-2；plan.md §4.1 第 3 步、§4.2.2 第 3 条 — 国图卷下的 `tiles/`（R-001 规定其内容不导入）以及其他不含可导入影像的子目录，按词表规则是「词表外子目录」，会「自成写卷单元并列入异常」，使「词表外子目录 1 个」无法成立；plan 只把 tiles 文件记入 excluded，§4.2.2 第 3 条仍会把目录本身判为词表外单元。— 修法：spec 写明只有含可导入影像（直接或更深层）的子目录才构成写卷单元或词表外异常；不含可导入影像的目录（`tiles/` 等）整体记入「未导入」清单并注明原因；plan §4.2.2 同步。

`[CHK-P2]` plan.md §4、§5 AC-010-1 — spec AC-010-1 要求的「隐藏文件与非隐藏影像同目录（待确认）」（Q-003 的 10 个）与「无馆藏号的写卷单元」两个类别，在 plan 的流程与规则里没有产生点，只靠 `test_anomaly_categories_complete` 兜底。— 修法：在 §4.2.2（划分单元时判定隐藏影像与非隐藏影像同目录）与 §4.2.3 第 3 条（没有合规馆藏号的单元）写明记录这两类异常，并在 §5 对应行注明。

### 非阻断建议

### 阻断问题

[R2-B-01] `specs/catalog-foundation/plan.md` §4.1 第 4 步、§4.2.1、§5 AC-003-7；`specs/catalog-foundation/spec.md` AC-003-7、Q-017 — **第 1 轮 B-02 未完全解决**。同根、同 inode、同五段指纹仍不足以排除 inode 复用：旧文件消失后，新文件复用了 inode，长度和五个采样区相同、仅未采样区域不同，会被第二行直接认作旧影像。该行也没有要求候选唯一及匹配一对一；例如多个硬链接记录同时换路径时，可能出现多个候选。现有合成文件条目测试不能替代对指纹生成与匹配组合的验证 — 补充能区分复用的身份依据及候选唯一性规则；不能可靠确认时按 AC-003-7 新建并报异常。增加「同采样区但其他区域不同＋inode 复用」「多个旧候选／多个新候选」的组合测试，不应仅把采样从两段增加到五段即视为闭环。

[R2-B-02] `specs/catalog-foundation/spec.md` R-003、Q-016；`specs/catalog-foundation/plan.md` §4.2.3 第 1、3、4 条 — **第 1 轮 B-03 的平局及身份选择问题仍未闭环**。「多数」没有说明是超过半数还是相对最多，分母是否包含新增影像，共享影像如何计数；无多数且并非全部新影像时也没有确定处理。计划自行加入「平局取 serial 较小者」，但 spec 没有批准这一身份取舍，也没有相应 AC — 回到 Clarify 明确计数、无多数、平局及共享影像的处理，并补验收规则；随后统一计划，不能仅在技术方案中决定哪个既有写卷取得这些影像。

[R2-B-03] `specs/catalog-foundation/plan.md` §4.2.3 第 1、4 条；`specs/catalog-foundation/spec.md` AC-002-4、AC-003-1、AC-003-6 — **新增问题：正常的多编号共享关系在重跑时会进入拆分分支**。例如 `P3012+5564` 首次导入建立两件写卷并共享全部影像；第二次导入时，该单元对两件写卷都满足影像归属条件，又具有两个目标 key，于是第 1 条会将既有正常关系判成「规则要求拆分」，第 4 条还可能对共享关系执行单选。已有多对多关系并不意味着发生了新的拆分 — 拆分检测应比较本次目标关系与既有关系，区分「维持合法共享」和「把原有单件重新分配」。增加多编号单元连续导入两次的测试，核对 ID、关联、编号及异常均不发生伪变化。

[R2-B-04] `specs/catalog-foundation/plan.md` §4.2.3 第 2 条；`specs/catalog-foundation/spec.md` AC-003-4、AC-003-5 — **新增问题：按旧 key 占用逐件处理会误合并同批编号纠错的写卷**。例如既有 A＝P.2002、B＝P.2003，两目录互换编号而各自影像不变，本次应保留两个 ID 并分别更新编号；按当前步骤，先处理任一件都会发现目标 key 被另一件占用，从而合并两件实际上具有不同本次编号的写卷 — 应先计算本批全部目标 key 与身份关系，再判断是否真正同号，批量处理 key 迁移；补充编号互换及连续变号测试，证明结果与遍历顺序无关。

[R2-B-05] `specs/catalog-foundation/spec.md` AC-013-1、Q-021；`specs/catalog-foundation/plan.md` §3「字段依据」；`AGENTS.md` §4、`docs/plan.md` §5 原则 2 — **第 1 轮 B-08 仅部分解决**。新增机制已覆盖来源类型、规则版本、批次、时间、置信度与历史，但没有规定每个字段的作者如何恢复。`import_run` 的触发人不等于字段作者；`provenance_history` 的 `rule:`／`user:` 判定者仅覆盖出处认定 — 为全部结构化字段明确作者约定，例如规则执行者与版本、人工作者账号，并保证历史查询能够恢复；可以通过规则或批次关联实现，无须冗余列，但必须写明关联语义并补 AC 和验证，不能默认触发人就是所有字段的作者。

### 阻断问题

`[CHK-R003 / CHK-02 / CHK-P2]` spec.md R-003 影像第 1、2 条、AC-003-7、AC-009-2；plan.md §4.2.1 第 1、2 行与 §5 对应行 — 影像身份在「缺失后再出现」时未定义。具体情形：某 TIFF 被从 File Station 删除（DSM 把它 rename 进同一共享文件夹的 `#recycle`，inode、大小、修改时间不变），导入一次后该影像标「缺失」；随后从回收站还原到原路径，再导入。spec 影像第 1 条按字面是同一位置、同一影像；plan 第 1 行只匹配 present 影像，第 2 行的候选「本次不在原路径的影像」对这条已缺失记录既可读作包含也可读作不包含，最终落到第 3 行：新影像 + 「身份待确认」，旧记录永久缺失。同样的还原若发生在两次导入之间（中间没有导入），则走第 1 行、ID 不变。结果取决于中间是否导入过，违背 R-003「一经分配不再改变」的意图，也使 R-009「只标记、不删除」失去恢复意义；AC-003-7、AC-009-2 都没有覆盖这一情形。— 修法：登记 Q-038，在 R-003 影像第 1 条写明「记录已标缺失的位置上再出现文件时仍是同一影像：状态回到 present，记『重新出现』，内容变化记变化历史」（或至少在 inode、大小、修改时间、抽样内容与缺失记录相同时延续，其余按第 1 条处理）；第 2 条写明候选是否包含早先已缺失的影像；新增 AC（如 AC-009-5：删除 → 导入 → 还原 → 导入后影像 ID 与写卷关联不变、不产生身份待确认）；plan §4.2.1 第 1、2 行按此改写，§5 补对应测试。

### 阻断问题

`[CHK-R003 / CHK-02]` spec.md AC-003-7、AC-003-9；plan.md §5 对应两行 — AC-003-7 的总述「不能唯一确认身份时不猜测延续」与所列情形「文件编号被复用、大小与抽样内容相同而修改时间不同的文件」「同一内容的重复副本」没有写明文件出现在什么位置。按 R-003 影像第 2 条，若这些文件出现在仍有影像记录的位置上（例如删掉原文件后在原路径放入复用了文件编号的新文件，或用 `cp` 以副本覆盖原文件），应延续该位置的影像并记内容变化；plan §4.2.1 第 3 行也是这样处理。AC 却要求「作为新影像导入并列入身份待确认」，对同一输入给出相反预期；plan §5 的测试用「文件条目组合」构造 inode 复用，最自然的构造正是放回原路径。AC-003-9 的「三个目录连续变号」若末号仍被持有（X：2602→2603，Y：2603→2604，Z 保持 2604），按写卷第 4 条结果是 X、Y 退回并列「身份待确认」，这正是 AC-003-5 第三种情形，与 AC-003-9 要求的「各写卷分别更新编号」相反。— 修法：AC-003-7 加限定「这些文件出现在没有影像记录的位置上」，总述改为「不能确认是同一文件、所在位置又没有影像记录时不猜测延续」；AC-003-9 写明三个目录是编号轮换（2602→2603→2604→2602）或整体顺移到未被持有的编号；plan §5 两行的测试说明同步写明位置与终点。

### 阻断问题

[R4-B-01] `specs/catalog-foundation/plan.md` §4.1 第 4 步、§4.2.1 第 1 行；`specs/catalog-foundation/spec.md` R-003 影像第 1、2 条、Q-030 — 快速路径只凭位置、inode、大小和修改时间相同就沿用旧事实与指纹，不能证明抽样内容相同。例如对已登记 TIFF 原位写入同长度内容，再还原 `mtime_ns`：inode、大小和修改时间不变，但文件头或采样区已经改变。plan 会继续使用旧事实、不记变化；spec 则应按位置延续影像并记录内容变化。这不属于 Q-030 接受的“抽样内容也相同、只有未抽样区域不同”的残余风险 — 建议在复用事实前校验本次抽样内容，或明确采用其他可靠变更依据；如确实要接受更宽的漏检范围，须回 Clarify 明示并重新批准。补充保持 inode、大小和修改时间不变但修改文件头／采样区的测试。

[R4-B-02] `specs/catalog-foundation/plan.md` §4.2.1 第 1、2 行；`specs/catalog-foundation/spec.md` R-003 影像第 1～3 条、AC-003-7 — 先认领稳定位置、再仅对“未被认领”的对象判断唯一性，会把全局不唯一变成局部唯一。例如首次导入同一文件的两个硬链接 `x.tif`、`y.tif`，分别为 Ix、Iy；随后保留 x，将 y 改名为 z。两条旧记录及两个当前文件的 inode、大小、修改时间和指纹均相同。spec 第 1 条不能唯一确认任何一对，第 2 条只能按位置延续 Ix，z 应新建并报身份待确认；plan 却先认领 x→Ix，再把剩余的 z→Iy 当成一一对应的改名 — 建议在位置快速路径消耗候选之前，按完整比较集合确定唯一性，不能因提前认领而消除歧义；若要允许这种位置辅助消歧，应回 Clarify 改规则及 AC。补充“一条硬链接位置不变、另一条移动”的组合测试。

[R4-B-05] `specs/catalog-foundation/plan.md` §4.7“健康采样”、§4.8“命令行用于测试与恢复”、§5 AC-012-3；`specs/catalog-foundation/spec.md` R-012、AC-012-3、Q-044 — CLI 导入没有登录状态时，把健康接口两秒内返回的任意状态码都当作正常。这与 API 导入要求的 HTTP 200 且 `ok=true` 不同：401 只证明登录墙在响应，持续的 500／503 也会被 CLI 当作正常，因而不会触发暂停和十分钟中止。当前 spec 没有给予恢复导入这项例外 — 建议实际 NAS 导入统一使用可验证健康状态的判据；CLI 应接收触发者自己的有效登录状态并仅驻留内存，或在无法验证时拒绝执行实际导入。补充 CLI 的未认证、错误状态和暂停／中止测试；如保留降级例外，须先回 Clarify 明确范围。

### 阻断问题

[R5-B-01] `specs/catalog-foundation/spec.md` R-003 影像判定第一步、AC-009-5 末句、Q-047、Q-050；`specs/catalog-foundation/plan.md` §4.2.1 第 1、2 行、§5 AC-009-5 — 新的位置优先规则与“原位置放入另一条已登记影像的文件时，随文件延续那条影像”仍有相反预期。具体情形：同根内 `x.tif`、`y.tif` 是一对硬链接，已分别登记为 Ix、Iy；删除 x 并导入，Ix 标为缺失；再把 y 改名到 x，inode、大小、修改时间均保持不变。按 R-003 第一阶段及 plan 第 1 行，x 直接认领缺失的 Ix，Ix 重新出现、Iy 缺失；但 AC-009-5 末句要求延续从 y 移来的 Iy、Ix 继续缺失。此例不涉及 inode 复用，也不属于 Q-047 接受的内容变化漏检。— 建议回 Clarify 明确此交叉情形：若保持 Q-047 的位置优先取舍，应将 AC-009-5 末句限定为“未被位置第一阶段认领，且随后可唯一确认属于另一条影像”，并明确上述硬链接情形的预期；同步增加三次导入的真实硬链接测试，不能只测试普通的非硬链接文件移入。

[R5-B-02] `specs/catalog-foundation/spec.md` AC-009-5 第三种还原情形、R-003 影像第 1～3 条、Q-038、Q-050；`specs/catalog-foundation/plan.md` §4.2.1、§5 `test_reappearance_keeps_ids` — “原样还原到同一写卷单元中的另一位置”只限制了单元，没有限制还原方式及身份条件。把文件真正删除并导入后，从备份复制字节完全相同、修改时间也相同的文件到该单元的新路径，inode 会不同：新位置没有影像记录，文件身份匹配又因 inode 不同而失败，按规则应新建影像、记“身份待确认”，旧影像继续缺失；AC-009-5 却要求恢复原 ID、不记异常。因此“原样”尚不能形成唯一、可执行的验收前提。— 建议明确区分“同根内保留 inode 等确认信息的回收站还原／移动”和“复制重建文件”：前者满足唯一匹配时恢复原影像，后者在无位置可延续时按 R-003 第 3 条处理；将条件写入 AC，并分别测试。若希望复制还原也自动延续，则须另行澄清其与重复副本不猜测延续规则的关系，不能仅修改测试夹具。

[R5-B-03] `specs/catalog-foundation/plan.md` §4.1 第 4 步、§4.2.1 第 1 行、§5 AC-005-1；`specs/catalog-foundation/spec.md` R-005、AC-005-1、Q-019 — 读取失败分支仍有两处设计缺口：第一，计划把七个事实字段全部记为“缺失”，但 AC-005-1 明确要求 PSB 的分辨率、压缩方式、软件标签，以及 JPG 的压缩方式、软件标签为“不适用”，读取失败不应改变文件种类对应的不适用集合。第二，下一次导入只要位置、inode、大小、修改时间相同，就复用上述失败结果及空指纹；例如首次读取遇到临时 I/O 错误，下一次已可正常读取但这些元数据未变，计划仍不会重试，事实将永久停留在错误的缺失状态。— 建议单独保存读取成功／失败状态，失败记录不作为成功事实缓存复用，并明确恢复后的重试与异常消除规则；不适用字段始终按种类填写。补充“首次读取失败、第二次读取成功且文件元数据完全未变”的测试，以及不可读 PSB、JPG 的字段状态断言；正常文件的 Q-047 快速路径可继续保留。
