# D-008 原始数据写入例外：拼接输出写回卷目录

- 日期：2026-10-27（追认登记；决策早于本文件）
- 状态：accepted

## 背景

拼接工作台需要把多段扫描拼成一卷，并让结果像普通分段一样参与浏览与图块生成。
现行实现由查看器直接写回原图目录（`app.py` `_stitch_build_worker`），为此查看器容器以 rw 挂载 `/srv/example/data`，两个生成器保持 ro（`docker-compose.yml`）。

## 备选方案

- 输出到 `cache/stitch_out/`，由宿主机 `stitch_apply.py` 搬入卷目录，查看器保持只读挂载。该通道的脚本仍在，但 `app.py` 已不再向 `stitch_out/` 写入（去留见 `plan.md` §9）

## 结论

- 原始数据目录唯一允许的写入：拼接工作台输出 `<卷目录>/合并长卷.tif`
- 写法：先写同目录临时文件 `.合并长卷_building_<ts>.tif`，确认非空后原子替换（覆盖同名旧文件）
- 其他任何代码路径不得写原始数据目录；新增写入路径须先登记新 ADR

## 取舍理由

拼接结果立即成为卷的一段，复用全部浏览与图块管线；代价是查看器获得了原图目录的写权限。

## 影响

- `docker-compose.yml`（查看器 `/data:rw`）、`app.py` 拼接工作台
- 风险见 `plan.md` §10；流程见 `architecture.md` §6
