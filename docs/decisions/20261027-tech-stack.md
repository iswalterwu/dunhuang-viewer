# D-016 前后端分离的方式与技术选型

- 日期：2026-10-27
- 状态：accepted（plan.md PD-17，用户按建议确认）

## 背景

D-011 确定前后端分离，分离方式与选型待定。v0 查看器在线服务，不能因迁移中断。

## 备选方案

- 一次性重写，替换 v0
- 数据库用 SQLite
- 其他前端框架（如 React）

## 结论

1. 渐进迁移：Phase 1 的新功能（目录、标注、浏览）直接按「API + 新前端」实现；v0 查看器继续在线，新前端覆盖其功能后再替换
2. 数据库：PostgreSQL
3. 前端：Vue 3 + Vite + TypeScript（与 related-project 一致）
4. 影像服务方案（IIIF Image API 的实现方式）在首个涉及影像服务的 feature 中另行登记 ADR

## 取舍理由

- 渐进迁移让 v0 持续服务，风险可控
- PostgreSQL 支持并发写入、全文检索与 JSON，适合多用户、标注历史与 Phase 3 的协作
- Vue 3 与已有项目一致，心智负担低

## 影响

- 新增的后端服务与数据库运行在 受限内存的 NAS 上，上线前必须评估内存，并遵守 D-005 红线（plan.md RK-01）
- `catalog-foundation` 的 plan.md 给出部署方案
- D-002（单体后端）与 D-004（原生前端）在 v0 被替换时由新 ADR 取代
